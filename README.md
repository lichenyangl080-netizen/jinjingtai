# 进境台桌面版

Windows 本地工作进展记录工具：把每天做过的事、发现与下一步留下来，按工作台、项目和回望阅读。工作台提供今日/日历切换，界面采用黑白水墨风格，资料保存在自己的文件夹中。

当前源码版本为 **0.2.12 预览版**，面向 Windows x64。欢迎试用和反馈；其他系统及另一台全新 Windows 的完整 Codex 接入尚未验收。

## 当前功能

- 无需连接 Codex 就能建库、手写补记、编辑、添加附件和回望。
- 接收授权 Codex 工作的阶段记录，区分已验证成果、未验证实现、尝试、建议和决定；整理由用户主动发起，通过检查后直接保存。
- 支持项目命名、未来一个月内的手动规划、阅读字号、资料备份与切库。
- 本地全文搜索找回正文与心得，项目概况和继续起点分别维护；跨日主线人工组织，周/月/年回望自由写作并引用记录。
- 接入向导的检查与等待回执状态在本次软件会话中跨页面保留；详情可直接用于继续起点、主线或回望，编辑失败保留输入。
- JSON与附件为权威资料，SQLite仅为可重建索引；损坏或缺失不自动重建空库。

## 使用桌面包

将完整分享包解压到普通文件夹，运行 `进境台.exe`。首次点击“创建或选择资料库”，之后可以直接补记。需要采集时在“设置 → Codex连接”设置连接并审阅新增 Hook。

从 [Releases](https://github.com/lichenyangl080-netizen/jinjingtai/releases) 下载页面实际提供的 `jinjingtai-windows-x64-<版本>.zip`，并核对附件版本。源码可能领先于已发布的下载包；本地构建完成不表示新版已上传。客户端包含所需运行组件，无需另装 Node 或 Electron；Codex 接入组件由设置界面安装，Codex 本身需自行安装并登录。源码包供开发者使用，普通用户无需下载。完整步骤见 [使用说明](docs/使用说明.md)。不要转发含自己状态配置的程序目录。

## 从源码运行与验证

当前桌面目标为 Windows。请使用 `.node-version` 指定的 Node 24.19.0 与锁文件中的 Electron版本。发行包压缩携带实际构建用的独立 Node，安装连接时校验摘要并解压到运行目录；后台不占用桌面程序文件。缺少实际版本对应的完整许可文件时，打包明确失败。

完整中文字体采用无损 WOFF 压缩，保留全字集。桌面包保留中文与英文回退语言。`npm run clean:artifacts` 清理已识别的历史产物：更新事务完成后清理旧程序，只保留最新一份分享包，限制诊断、验收截图与旧验收 profile；遇到资料文件、链接或未知目录会保留并报告原因，不清理正文、附件或备份。

```powershell
npm ci
npm run build
npm run check
npm start
```

`npm run build` 生成桌面界面及 Sites 验收需要的完整构建产物，之后再运行检查。`npm run format:check` 检查源码格式。`npm run package:share` 会先构建，生成不含个人配置的分享目录，仅保留最新一份；`npm run package:desktop` 生成原位更新包，保留状态位置和 profile。旧程序仅在更新事务中临时保留用于失败回滚，成功切换后自动清理；含个人资料或无法确认归属的目录保留并报告。源码、开发依赖及个人资料不参与此清理。两种包使用同一份源码元数据、使用说明和许可文件。

Windows CI执行锁文件安装、检查、构建和隔离分享打包。验证与测试必须使用新建的 `JINJINGTAI_HOME`、`JINJINGTAI_PROFILE`、`CODEX_HOME`，不得写入实际资料库。

## 数据与模型边界

日常手写、阅读和编辑无需模型或网络。不保存API Key，不复制登录凭据，不读取完整历史聊天。整理只发送核准的阶段材料；人工正文、回顾、规划和附件不进入模型。无新增不调用模型，不自动重试或后台总结。

来源适配检查真实数据契约，Codex 版本号仅作诊断；缺字段、未知状态或来源歧义明确报告，不冒充完整历史覆盖。可信 MCP＋Hook 保存自有阶段，历史接口异常不清空已有资料。发行前仍需在另一台干净 Windows 电脑验收首次安装、真实 Hook 信任、记录与整理；本地隔离验收不代替此项。

## 代码结构与贡献

前台结构：Workbench → views + useWorkspace → model/day-state/work-progress；样式仅workspace.css。接入结构：connection（事务配置）、source/source-adapter（真实来源）、mcp/verification（记录校验）、store（JSON权威与缓存）、consolidate/job-policy（整理及历史重放）、material-reader（限权读取）。

新增逻辑应归入现有职责，避免把业务保存堆入页面组件。useWorkspace仍集中页面交互，后续按实际功能改动拆分，不以大规模重写代替具体问题修复。

普通问题和功能建议通过 [GitHub Issues](https://github.com/lichenyangl080-netizen/jinjingtai/issues) 提交，仓库提供反馈模板。请说明触发步骤、应用/Codex版本与错误码，使用虚构材料复现。安全或隐私问题按 [安全反馈说明](SECURITY.md) 联系，避免在公开问题中贴正文、附件、凭据或原始来源。提交修改前运行检查与构建，为真实缺陷补回归测试。
